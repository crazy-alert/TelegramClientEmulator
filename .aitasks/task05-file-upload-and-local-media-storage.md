# Задача 05: Multipart upload и локальное media-хранилище

## Цель
Поддержать реальные локальные файлы для изображений и документов в Docker-first окружении.

## Ожидаемый результат
- Реализовано настраиваемое локальное media-хранилище в runtime-директории.
- Bot API media methods принимают multipart file upload там, где это канонично для Telegram Bot API.
- UI может прикреплять файл пользователя и отправлять его как update.
- Возвращаемые `file_id`/`file_unique_id` стабильны для сохраненного файла.
- Добавлен безопасный лимит размера и запрет path traversal.
- Документация описывает storage path, ограничения и Docker volume.

## Примечания
- Не коммитить реальные пользовательские файлы.
- При изменении import/export формата подумать об archive/manifest отдельно.
