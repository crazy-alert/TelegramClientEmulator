# Правила для AI-ассистентов

## Назначение проекта

Проект представляет собой Docker-ориентированный локальный эмулятор для разработки и тестирования Telegram-ботов.

Основной продукт: веб-интерфейс, который минимально имитирует чат Telegram и отправляет похожие на Telegram Bot API webhook-обновления в контейнер с ботом разработчика.

## Язык проекта

- Ответы пользователю должны быть на русском языке, если пользователь явно не попросил другой язык.
- Сообщения коммитов должны быть на русском языке.
- Техническая документация должна быть на русском языке.
- Markdown-файлы должны быть на русском языке.
- Комментарии в коде должны быть на русском языке.
- Документационные блоки в коде, включая JSDoc, TSDoc, PHPDoc, Python docstring и аналогичные форматы, должны быть на русском языке.
- Имена переменных, функций, классов, API-полей, путей и технических идентификаторов на русский язык не переводить без необходимости.

## Инженерные принципы

- Предпочитать простую и явную реализацию широким абстракциям.
- Держать совместимость с Telegram сфокусированной на реальных задачах разработки.
- Для неподдерживаемых методов Telegram Bot API возвращать понятные ошибки, а не молчаливые заглушки.
- Сохранять Docker-first workflow.
- Аккуратно относиться к `localhost` в документации и коде: внутри Docker Compose сервисы обычно должны обращаться друг к другу по именам сервисов.
- Хранить постоянные данные разработки в настраиваемой директории.
- Не подключаться к настоящему Telegram, если будущая задача явно не попросит такой режим.

## Ожидаемая архитектура

- Backend HTTP server:
  - API профилей;
  - API сообщений;
  - диспетчер webhook;
  - локальные маршруты, совместимые с Bot API.
- Frontend:
  - Telegram-like интерфейс чата;
  - переключатель и редактор профилей;
  - инспектор запросов и ответов.
- Хранение:
  - SQLite или другое небольшое локальное файловое хранилище.
- Runtime:
  - Docker и Docker Compose должны оставаться основным способом запуска.

## Стиль кода

- Следовать существующим соглашениям проекта после появления реализации.
- Если выбран Node.js, предпочитать TypeScript.
- Типы request/response payload должны быть явными.
- Добавлять сфокусированные тесты для генерации webhook payload, поведения Bot API routes и хранения данных.
- Не добавлять production-only инфраструктуру для задач локальной разработки.

## Правила документации

- Обновлять `README.md`, когда меняются запуск, порты, переменные окружения или Docker usage.
- Обновлять `docs/technical-spec.md`, когда меняется продуктовый scope или архитектура.
- Явно документировать неподдерживаемые методы Telegram Bot API.
- Добавлять Docker Compose примеры интеграции с ботом.
- Новые `.md` файлы писать на русском языке.
- Комментарии и документационные блоки в коде писать на русском языке.

## Безопасность

- Не коммитить секреты, реальные bot token и реальные данные пользователей Telegram.
- Использовать фейковые примеры вроде `123456:local-dev-token`.
- Не удалять пользовательские файлы или настройки IDE без явного запроса.
